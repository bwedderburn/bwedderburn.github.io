The engineering problem

Keep commands and feedback coherent.

Playback, track metadata, and display updates cross several interfaces. A command may begin at a touchscreen or a wireless remote, while the response comes back through the audio module or a metadata helper.

The work is in coordinating those paths: parsing messages, scheduling updates, handling disconnects, and keeping the controls responsive while background work continues.

Implementation

Follow each interface.

Audio controller

CircuitPython on the ESP32-S3 handles BM83 UART messages, playback controls, and metadata. Deferred work keeps incoming events separate from longer operations.

Local and wireless displays

The Nextion provides a serial touchscreen interface. The CrowPanel remote uses a separate C++ / LVGL application and ESP-NOW messages for controls and state updates.

Badge remote

A GitHub Universe 2026 badge app adds another control interface. Its BMW1 protocol has a receiver in the current controller source.

Press and release behavior

Volume control includes the end of a press, as well as its beginning. The project also addresses connection recovery, bounded work, and consistent display state.

Evidence

Checks with a defined scope.

The project includes host tests and documented checks on the physical system. Each validation record identifies the route, conditions, and limitations of that run.

A documented Mac/helper route completed a scoped 30-minute physical acceptance run. That result applies to the recorded setup; other platforms, startup sequences, and recovery scenarios have their own acceptance work.

Release preparation

A reviewable candidate.

A 1.0.0 release candidate is prepared locally, with selected controller and badge source, compiled controller libraries, and recorded checksums. It includes the latest reviewed build dependency updates.

The candidate’s focused runtime tests and synthetic NVS and encryption checks passed. Native runtime images and hardware installation have their own validation steps. The browser demo is a separate presentation of the remote interface.
